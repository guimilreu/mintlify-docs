---
title: "Criar webhook"
description: "Cria uma nova assinatura de webhook para receber eventos da SocialSell."
---

## Endpoint

```
POST /v1/webhooks
```

**Escopo necessário:** `write:webhooks`

## Corpo da requisição

| Campo | Tipo | Obrigatório | Descrição |
|-------|------|-------------|-----------|
| `name` | string | Sim | Nome descritivo (máx. 100 chars) |
| `url` | string | Sim | URL HTTPS de destino |
| `events` | string[] | Sim | Mínimo 1 evento. Ver lista abaixo |

### Eventos disponíveis

São 47 eventos, em 13 grupos. A [referência de eventos](/webhooks/events) lista todos com o payload
exato de cada um. Um evento fora da lista faz a requisição falhar com `validation_error`.

<Note>
  A URL precisa ser **HTTPS** e resolver para um endereço público. `localhost`, redes privadas e faixas
  reservadas são recusadas com `422 SSRF_BLOCKED`, tanto aqui quanto no momento de cada entrega.
</Note>

## Exemplo de requisição

```bash
curl -X POST https://api.socialsell.ai/v1/webhooks \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Integração CRM Interno",
    "url": "https://meusistema.com/webhook/socialsell",
    "events": ["deal.won", "proposal.accepted", "channel.disconnected"]
  }'
```

## Exemplo de resposta

```json
{
  "data": {
    "id": "664058b720a5c5631521ca8f",
    "name": "Integração CRM Interno",
    "url": "https://meusistema.com/webhook/socialsell",
    "events": ["deal.won", "proposal.accepted", "channel.disconnected"],
    "status": "active",
    "secret": "whsec_a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6",
    "last_delivery_at": null,
    "last_failure_at": null,
    "consecutive_failures": 0,
    "created_at": "2026-06-10T16:00:00.000Z",
    "updated_at": "2026-06-10T16:00:00.000Z"
  }
}
```

Retorna `HTTP 201`.

<Warning>
O campo `secret` é exibido **apenas nesta resposta**. Armazene-o imediatamente como variável de ambiente para usar na validação de assinaturas. Não é possível recuperá-lo depois.
</Warning>

## Validando entregas

Use o `secret` para conferir a assinatura de cada requisição recebida. Os exemplos em Node, Python, PHP e Go estão em [Segurança e verificação](/webhooks/security).

## Erros

| Status | Código | Quando acontece |
| --- | --- | --- |
| `400` | — | `name`, `url` ou `events` ausente ou inválido; evento fora do catálogo |
| `403` | `WEBHOOK_LIMIT_REACHED` | Limite de endpoints do plano atingido, ou plano sem direito a webhooks |
| `422` | `SSRF_BLOCKED` | URL não-HTTPS, com credenciais embutidas, ou apontando para rede privada |
