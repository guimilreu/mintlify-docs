---
title: "Marcar como perdido"
description: "Marca um negócio como perdido (status: lost)."
---

## Endpoint

```
POST /v1/deals/:id/lost
```

**Escopo necessário:** `write:deals`

## Corpo da requisição

| Campo | Tipo | Obrigatório | Descrição |
|-------|------|-------------|-----------|
| `closed_date` | string | Não | Data de fechamento. Padrão: data atual |
| `reason` | string | Não | Motivo da perda. Gravado em `loss_reason`, **cortado em 200 caracteres** |

## Exemplo de requisição

```bash
curl -X POST https://api.socialsell.ai/v1/deals/664c1d2e3f4a5b6789012347/lost \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{"reason": "Preço acima do orçamento do cliente"}'
```

## Exemplo de resposta

```json
{
  "data": {
    "id": "664c1d2e3f4a5b6789012347",
    "title": "Proposta Enterprise ACME",
    "status": "lost",
    "closed_date": "2026-06-10T00:00:00.000Z",
    "loss_reason": "Preço acima do orçamento do cliente"
  }
}
```

Dispara o evento `deal.lost` em webhooks configurados.

<Tip>
O motivo da perda é o dado mais usado em relatório de funil. Envie sempre `reason` — sem ele, `loss_reason` fica `null` e a análise perde a causa.
</Tip>

## Erros

| Código | Status | Descrição |
|--------|--------|-----------|
| `INVALID_ID` | `400` | ID com formato inválido |
| `NOT_FOUND` | `404` | Negócio não encontrado |
